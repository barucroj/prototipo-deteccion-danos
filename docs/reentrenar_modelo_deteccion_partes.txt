REENTRENAR EL MODELO DE DETECCION DE PARTES DE AUTO
Proyecto: prototipo-deteccion-danos
=====================================================

Para relanzar un entrenamiento solo necesitas correr:

    python -m src.detection.train

desde la raiz del proyecto. Los archivos relevantes y que se pueden
modificar son estos:

1) C:\Users\barucroj\Desktop\IPN\TTR\Code\prototipo-deteccion-danos\src\detection\train.py
   -----------------------------------------------------------------------------
   Es el punto de entrada. No hace falta editarlo: todo se controla con
   flags de linea de comandos (ver argparse dentro del archivo). Los mas
   importantes:

   --epochs N            numero de epocas (default 10)
   --batch-size N         imagenes por batch (default 2)
   --lr LR                learning rate (default 0.005)
   --max-train-images N   limita el train set (usalo SOLO para pruebas rapidas,
                           quitalo para un entrenamiento real con las 333 imagenes)
   --data-root DIR         carpeta del dataset (default "data/raw/Car parts coco-segmentation")
   --output DIR            donde se guardan los checkpoints (default "models/checkpoints/test")
   --device cpu|cuda       si en algun momento tenes GPU con CUDA, cambialo a cuda

   Ejemplo de reentrenamiento real (no smoke test):
       python -m src.detection.train --epochs 20 --batch-size 4 --output models/checkpoints/v2

2) C:\Users\barucroj\Desktop\IPN\TTR\Code\prototipo-deteccion-danos\src\detection\model.py
   -----------------------------------------------------------------------------
   Aca se define la arquitectura (funcion build_model). Actualmente usa
   fasterrcnn_mobilenet_v3_large_320_fpn (liviano, pensado para CPU).

   Si tenes GPU o mas tiempo y queres mas precision, cambia esa linea por
   un backbone mas pesado, por ejemplo:
       from torchvision.models.detection import fasterrcnn_resnet50_fpn_v2, FasterRCNN_ResNet50_FPN_V2_Weights
       weights = FasterRCNN_ResNet50_FPN_V2_Weights.DEFAULT if pretrained else None
       model = fasterrcnn_resnet50_fpn_v2(weights=weights)
   (el resto de la funcion, el reemplazo del box_predictor, queda igual)

3) C:\Users\barucroj\Desktop\IPN\TTR\Code\prototipo-deteccion-danos\src\detection\dataset.py
   -----------------------------------------------------------------------------
   Ahora mismo NO aplica data augmentation (solo convierte la imagen a
   tensor). Si el modelo da overfitting (train_loss baja pero val_mAP no
   mejora), se le pueden agregar transforms aca dentro de __getitem__
   (flips horizontales, jitter de color, etc. con torchvision.transforms.v2,
   ajustando tambien las boxes si haces flip).

4) C:\Users\barucroj\Desktop\IPN\TTR\Code\prototipo-deteccion-danos\src\detection\engine.py
   -----------------------------------------------------------------------------
   Control de la metrica de validacion (mAP@0.5). Si queres medir con otro
   umbral de IoU, cambia iou_threshold en la funcion evaluate() (o pasalo
   como argumento si lo llamas tu mismo desde un script nuevo).

5) C:\Users\barucroj\Desktop\IPN\TTR\Code\prototipo-deteccion-danos\models\checkpoints\
   -----------------------------------------------------------------------------
   Ahi se guardan los checkpoints (best_model.pth, last_model.pth,
   metrics.json). Esta carpeta esta en .gitignore, o sea que los .pth NO
   se suben a GitHub — quedan solo en tu maquina. Usa --output con un
   nombre distinto por corrida para no pisar el checkpoint anterior
   (ej: models/checkpoints/v2, models/checkpoints/v3-resnet50, etc).

RECOMENDACIONES DE COMBINACIONES
=====================================================
- Prueba rapida (validar que el pipeline corre, ~2-5 min):
      python -m src.detection.train --epochs 2 --max-train-images 40

- Entrenamiento real en CPU (tarda bastante, dejalo corriendo tranquilo,
  posiblemente varias horas para muchas epocas):
      python -m src.detection.train --epochs 20 --batch-size 2

- Si el batch-size 2 tira error de memoria, bajalo a 1. Si te sobra RAM y
  el entrenamiento anda lento, subilo a 4 (mas rapido por epoca pero cada
  paso pesa mas).

- Con solo 333 imagenes de train, mas epocas ayuda hasta cierto punto y
  despues empieza a sobreajustar (mira val_mAP en metrics.json: si empieza
  a bajar mientras train_loss sigue bajando, es overfitting -- ahi conviene
  quedarte con el best_model.pth de esa corrida, que ya guarda el mejor
  segun validacion, no el ultimo).

- Cambiar a fasterrcnn_resnet50_fpn_v2 (paso 2) da mejor precision pero es
  varias veces mas lento en CPU. Solo vale la pena si conseguis GPU o si
  no te importa esperar mucho mas por epoca.

Para correr inferencia con el checkpoint que entrenaste:
    python -m src.detection.predict models/checkpoints/v2/best_model.pth ^
        "data/raw/Car parts coco-segmentation/test" models/checkpoints/v2/preview
