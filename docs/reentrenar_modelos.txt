REENTRENAR LOS MODELOS DE DETECCION
Proyecto: prototipo-deteccion-danos
=====================================================

Hay DOS detectores y comparten el mismo pipeline. Solo cambia la config:

  1) PARTES DEL AUTO (M2)   src/detection/car_parts/
     Dataset: data/raw/Car parts coco-segmentation/  (47 categorias de partes)
     Dos configs en car_parts/config.py:
       CONFIG       v1, Faster R-CNN, solo cajas     -> car_parts.train
       MASK_CONFIG  v2, Mask R-CNN, cajas + mascaras -> car_parts.train_masks
     La que pide la tesis es v2: M3 cruza mascaras de dano con mascaras de parte.

  2) DANOS (M3)             src/detection/damage/      Mask R-CNN, cajas + mascaras
     Dataset: data/raw/CarDD_release/CarDD_release/CarDD_COCO/  (6 tipos de dano)
     dent, scratch, crack, glass shatter, lamp broken, tire flat.

IMPORTANTE: usa siempre el interprete de venv_cuda (es el unico con GPU).

IMPORTANTE 2: cada entrenamiento va en una carpeta --output NUEVA.
   Si reusas una carpeta, al terminar la primera epoca se sobrescribe
   best_model.pth, se reemplazan last_model.pth, metrics.json, status.json y
   run_info.json, y train.log queda con las dos corridas mezcladas.
   models/checkpoints/ no esta en git: lo sobrescrito NO se recupera.
   OJO con los defaults: car_parts.train escribe en car_parts/v1 (el modelo v1)
   si no pasas --output. damage.train ya escribe por default en damage/v2.

Todo se controla con flags, no hace falta editar codigo. Con --help ves la
lista completa. Los flags mas importantes (identicos para todos):

    --epochs N            numero de epocas
    --batch-size N        imagenes por batch (2 es el maximo comodo en 6 GB)
    --lr LR               learning rate (default 0.005)
    --output DIR          donde se guardan los checkpoints (usar carpeta nueva)
    --device cpu|cuda     default: cuda si esta disponible
    --no-amp              apaga precision mixta (AMP esta ON por default en GPU)
    --eval-every N        evaluar cada N epocas (la ultima siempre se evalua)
    --lr-step-size N      baja el LR x0.1 cada N epocas
    --no-augment          apaga la augmentation (flip + color, ON por default)
    --seed N              semilla (default 42; -1 = sin semilla). Fija random,
                          numpy, torch y torch.cuda, pero cuDNN NO es
                          determinista: es "semilla fija", no "reproducible".
    --select-by bbox|segm que COCO AP@0.5:0.95 elige best_model.pth.
                          Default: segm en car_parts v2, bbox en car_parts v1
                          y en damage. segm exige un modelo con mascaras.
    --freeze-bn           deja las 69 BatchNorm2d en eval() al entrenar: sus
                          running_mean/var (de COCO) ya no se recalculan con
                          batches de 2 imagenes. Gamma/beta si siguen
                          aprendiendo. OFF por default: se decidira con una
                          corrida A/B en car_parts (misma semilla, con y sin).
    --no-class-map        ignora el class_map de la config y entrena con las
                          clases originales (solo aplica a car_parts v2, que
                          por default usa src/detection/car_parts/class_map.py).
    --max-train-images N  limita el train set  (SOLO para pruebas rapidas)
    --max-val-images N    limita el val set    (SOLO para pruebas rapidas)
    --metric coco|simple  coco (default) = COCO AP estandar via pycocotools,
                          comparable con papers. simple = la metrica casera
                          vieja. NO son comparables entre si.

1b) COMPARAR v1 CONTRA v2 (despues de entrenar v2)
   ---------------------------------------------------------------
   La seleccion del mejor checkpoint de cada version se hace con val (lo hace
   el trainer). El veredicto v1-vs-v2 se calcula en TEST:

       ./venv_cuda/Scripts/python.exe -m src.detection.car_parts.compare_versions \
           --v1 models/checkpoints/car_parts/v1/best_model.pth \
           --v2 models/checkpoints/car_parts/v2/best_model.pth \
           --split test --output models/checkpoints/car_parts/v2/compare

   Escribe compare_test.json y compare_test.md: experimento A (v1 en 47 clases
   vs v1 mapeado a las clases finales) y B (v1 mapeado vs v2, cajas, mas el
   mask AP de v2), AP por clase con instancias, bootstrap pareado por imagen
   (1000, semilla 0, IC 95%). Clases con <10 instancias: "poco fiable".
   Con --split valid avisa que ese split no sirve para el veredicto.
   Tarda ~20 s en test (16 imagenes) en la RTX 3050.

   Chequeo ya hecho: v1 contra si mismo en test da diferencia B = 0 exacta
   (models/checkpoints/car_parts/_compare_v1_vs_v1/).

4) PRUEBA RAPIDA (smoke test) ANTES DE UN ENTRENAMIENTO LARGO
   ---------------------------------------------------------------
   Valida que todo el pipeline corre de punta a punta en menos de un minuto:

       ./venv_cuda/Scripts/python.exe -m src.detection.car_parts.train_masks \
           --epochs 2 --max-train-images 20 --max-val-images 8 \
           --output models/checkpoints/car_parts/smoke_test_masks

       ./venv_cuda/Scripts/python.exe -m src.detection.damage.train \
           --epochs 1 --max-train-images 40 --max-val-images 20 \
           --output models/checkpoints/damage/smoke_test

   El AP que sale de ahi NO significa nada, solo se mira que no truene.


5) VER EL AVANCE DE UN ENTRENAMIENTO
   ---------------------------------------------------------------
   Desde OTRA terminal, mientras entrena:

       ./venv_cuda/Scripts/python.exe -m src.detection.common.watch \
           models/checkpoints/car_parts/v2

   Muestra epoca, batch, barras de avance, loss (total y por termino), LR,
   memoria GPU, ETA, mejor epoca e historial. Se refresca cada 5 s
   (--interval N, o --once para verlo una vez). Avisa si el status lleva mas
   de 2 min sin actualizarse (proceso muerto o colgado) y si hay losses NaN/inf.


6) QUE QUEDA EN --output
   ---------------------------------------------------------------
       best_model.pth   mejor epoca segun --select-by
       last_model.pth   ultima epoca
       metrics.json     por epoca: loss total y por termino, LR, tiempo, pico
                        de GPU, is_best, y el bloque COCO (bbox y segm)
       run_info.json    args, commit de git (y si habia cambios sin commitear),
                        versiones, GPU, semilla, tamanos del dataset e
                        instancias por clase. Commitear ANTES de entrenar para
                        que el commit identifique el codigo.
       status.json      estado en vivo y estado final (completed /
                        interrupted / failed con el error)
       train.log        todo lo impreso, con fecha y hora

   Los checkpoints se describen a si mismos (arch, num_classes, categories,
   select_by, seed, augmented), asi que para inferencia no hay que decirle
   de que modelo son:

       ./venv_cuda/Scripts/python.exe -m src.detection.damage.predict \
           models/checkpoints/damage/v1/best_model.pth \
           "data/raw/CarDD_release/CarDD_release/CarDD_COCO/test2017" \
           models/checkpoints/damage/v1/predictions_preview \
           -n 10 --score-threshold 0.5

   predict solo dibuja imagenes anotadas; no genera el JSON de M2 ni de M3.

   Para probar con una foto propia, con un explorador de archivos:

       ./venv_cuda/Scripts/python.exe tests/detection/damage-segmentation/manual_inference.py \
           models/checkpoints/damage/v1/best_model.pth


7) QUE ARCHIVO TOCAR SI QUIERES CAMBIAR ALGO
   ---------------------------------------------------------------
   src/detection/common/model.py       arquitecturas (build_faster_rcnn /
                                        build_mask_rcnn). Cambiar backbone aqui.
   src/detection/common/trainer.py     loop de entrenamiento, optimizador,
                                        checkpoints, flags del CLI. Se comparte:
                                        lo que cambies aqui aplica a TODOS.
   src/detection/common/engine.py      train_one_epoch y la metrica mAP@0.5.
   src/detection/common/audit.py       status.json, train.log, run_info.json.
   src/detection/common/watch.py       el monitor de avance.
   src/detection/common/coco_dataset.py  lectura de COCO y rasterizado de
                                        poligonos a mascaras.
   src/detection/car_parts/config.py   CONFIG (v1) y MASK_CONFIG (v2).
   src/detection/car_parts/class_map.py  clases originales -> clases finales.
   src/detection/car_parts/compare_versions.py  comparacion v1 vs v2.
   src/detection/damage/config.py      rutas y defaults del modelo de danos.

   Para agregar otro detector: crea src/detection/<nombre>/ con un config.py
   (un DetectorConfig) y los wrappers train.py / predict.py. No hay que
   copiar el pipeline.

   METRICA: por default se usa COCO AP estandar (pycocotools 2.0.11). Es la
   que se cita en la tesis. Para los modelos con mascaras se reportan bbox AP
   y segm (mask) AP.

   src/detection/common/coco_eval.py    evaluacion COCO estandar.
   src/detection/common/engine.py       metrica casera, solo de respaldo
                                        (--metric simple). NO comparable.
